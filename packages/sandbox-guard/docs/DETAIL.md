# 沙箱守卫

这个插件管两类权限：**工作区文件权限**（让沙箱能在工作区里供给写入授权）和**提权策略**（哪些超出工作区的操作可以自动放行）。两部分各自独立开关。

## 它解决什么问题

DSH 的 Windows 沙箱在某个工作区第一次运行受限命令时，会给该目录写入一套沙箱授权（沙箱能力 SID 的允许项、一条删除拒绝、一条 Low 完整性标签）。这一步要求目录同时满足两个条件：

- 当前登录用户是目录的**所有者**；
- 目录 ACL 授予当前用户**取得所有权**（WRITE_OWNER）。

所有者身份本身只隐含「读权限」和「更改权限」，**不含**「取得所有权」。因此，当工作区是从别处复制来的、由某个安装器创建、或继承链上只有一条「修改」权限时，沙箱写入授权会失败（`Win32 5` / sandbox-local 错误），此后该工作区里的每条受限命令都在启动前就失败。

本插件在第一次使用之前就把这个前置条件补齐，而不是等出错后再去修。

## 它做什么

- 检查工作区根目录（另外 3 层祖先仅作诊断信息，不会被修改）。
- 判定为「缺少取得所有权」时，为当前登录用户补上完全控制：同身份已有的权限项会**合并**为完全控制（容器继承 + 对象继承），不会产生重复权限项。
- 只写 DACL：走 `SetNamedSecurityInfoW` 的 DACL 段，不需要 `SeSecurityPrivilege`，也**不会碰**沙箱的 Low 完整性标签（SACL）。
- 修改前把原 DACL 与一份独立的恢复脚本写到报告目录；修改后重新读取 ACL 校验，校验不通过就用备份 DACL 原样还原。
- 每次检查/修复写一行记录到 `history.jsonl`，便于回溯。

## 它不做什么

- 不删除任何现有权限项，不动 Deny、SACL、所有者或继承标志。
- 不处理符号链接/重解析点、非目录路径、DACL 为 NULL 的目录（NULL DACL 表示「所有人完全控制」，往里加权限项会把它变成「只有这一条」，所以直接跳过并报告）。
- 当前用户既不是所有者、又没有「更改权限」时，不会尝试夺取所有权（那需要管理员权限），只报告「需手动处理」。
- 不改动沙箱自身的授权项（`S-1-4-*` 能力 SID 与相关的 Everyone 删除拒绝），那些由 DSH 自己管理。

## 什么时候自动运行

1. 插件加载后约 2.5 秒，扫描工作区注册表里的全部工作区。
2. 每个新会话创建时，检查该会话的工作目录。
3. 会话里第一次调用工具之前：如果该工作区还没检查过，会等检查（必要时修复）完成再放行，避免修复和第一条命令抢时间。每个会话、每个目录最多等一次，最多等 20 秒，超时也不会阻塞工具。

同一路径的结果缓存 60 秒。`autoRepair: false` 时只检查、不修改，问题只写进历史记录。

## 手动使用

对话里输入命令：

- `/acl` — 检查当前会话的工作目录
- `/acl prepare` — 修复当前会话的工作目录
- `/acl prepare-all` — 修复所有已注册工作区
- `/acl status D:\path\to\workspace` — 检查指定目录

智能体工具 `workspace_acl`：`action` 取 `status`、`prepare`、`prepare_all`，`path` 可选（默认当前会话工作目录）。适合在刚新建或选定工作区之后、运行第一条命令之前调用。

## 配置

在 profile 的 `cordis.patch.yml` 中改 `sandbox-guard` 行的 `config`：

| 字段 | 默认 | 说明 |
|---|---|---|
| `autoRepair` | `true` | 发现缺少取得所有权时直接补权限；`false` 只检查 |
| `checkOnSessionStart` | `true` | 新会话创建时检查其工作目录，并启用「第一次工具调用前等待」这一道闸门 |
| `scanOnActivate` | `true` | 插件加载后扫描全部已注册工作区 |
| `reportDir` | `~/.dsh/sandbox-guard` | 备份脚本与历史记录目录 |
| `powershell` | 空 | 指定 PowerShell 可执行文件；空则先试 `pwsh.exe`，再试 `powershell.exe` |
| `timeoutMs` | `180000` | 单次修复超时；大目录第一次传播继承项可能很慢 |
| `cacheTtlMs` | `60000` | 同一路径结果的缓存时间 |

提权部分用 `escalation.enabled` 与 `escalation.rules`，规则字段见上一节；两者都不写时保持关闭。

## 授权覆盖（reach）

沙箱授权是**一个常驻 ACE + 一条 Low 标签，落在工作区根上**。根上有了之后新建的子目录会继承；但**在授权之前就已经存在的子目录不会**。这些目录对受限进程（Low 完整性）一直是不可写的——表现就是根目录 `ready`，构建却写不进 `src-tauri/target`、`dist`、`.git`。

- `workspace_acl` 的 `reach`：只读扫描，报告有多少目录缺能力 ACE、多少缺标签、缺哪些（抽样）。
- `reach_repair`：把根上已有的那条 ACE 和那条标签原样补到缺失目录，逐个回读校验，改前写备份（含回滚脚本）。
- 命令：`/acl reach`、`/acl reach-repair`。

它**不推导**任何新东西：SID、掩码、继承标志都从根上已存在的那条 ACE 读出来，标签也是从根上读出后原样复制。根上还没有授权时（`no-grant`）直接跳过，不会自己造一条。

两条限制：

- 修复粒度是目录；文件本身不参与判定（文件继承所在目录，够了）。
- **沙箱边界是会话启动时的工作区**，用 `working_directory` 切目录不会把边界搬过去。所以验证某个工作区的覆盖，必须由在该工作区启动的会话来做。

## 提权策略：高于工作区、低于完全权限

沙箱只有三档（只读 / 工作区可写 / 完全权限），没有第四档。但每个受沙箱约束的工具都支持**单次提权**：`pwsh`、`bash`、`write`、`edit` 都能带 `sandbox_permissions` + `justification` 重试，正常情况下这一步会弹审批问你。

本插件把「问不问」接了过来：**规则命中就直接答复 `allowed-once`，不再打扰你；没命中就照旧交给你。**

### 规则字段

| 字段 | 作用 |
|---|---|
| `tools` | 覆盖哪些工具：`pwsh`/`bash` 按命令匹配，`write`/`edit` 按路径匹配 |
| `commandPrefix` / `commandPattern` | 二选一，对**整条命令**判定 |
| `pathPrefix` | 文件类工具：路径解析后必须在这个目录内 |
| `workdirPrefix` | 命令的工作目录必须在这里；留空则必须在会话工作目录内 |
| `maxMode` | 这条规则最多能放到哪一档，默认 `workspace-write`（最窄档） |
| `allowShellOperators` | 默认 `false`：命令里出现 `;` `\|` `&` `<` `>` 反引号 `$(` 一律不自动放行 |

### 硬性护栏

- `escalation.enabled` 默认 **false**；没有规则时插件不介入任何审批。
- 命令含 shell 连接符 / 重定向 / 子表达式 → 不自动放行，防止 `cargo fetch; 任意命令` 借前缀蒙混。
- 工作目录默认必须落在会话工作目录内。
- `maxMode` 缺省是最窄档，要放到完全权限必须显式写。
- 每条规则必须带 `id`；解析不了的正则、缺匹配器的规则在加载时**丢弃并报错**，不做宽松兜底。
- 插件只决定「答不答」，不执行任何命令；命令仍由原工具运行。

### 审计

每次提权写一行到 `<reportDir>/escalations.jsonl`：时间、会话、callId、工具、目标模式、命中规则、命令或路径、工作目录、**Agent 给出的理由**，以及未命中时的近似原因。会话日志里同时有审批服务自己的 `approval/asked` + `approval/decided` 记录。

- `escalation_policy` 工具：`list` 看规则、`test` 干跑一条、`audit` 看最近记录。
- 命令 `/grants`：同一份数据的口语版。

### 一个必须知道的顺序问题

审批是 waterfall。如果配置里还有别的回答者（Auto 审查、自动放行插件）排在前面，它可能先给结论，规则就轮不到。本插件用 `prepend` 注册以保证先判。

所以：**命中规则时本插件是更早、更确定的那一层；未命中时仍会落到别的回答者那里。** 想让未命中的提权一律回到你手上，需要把更宽的那个回答者关掉。

## 回滚

每次修改都会在 `reportDir` 下留下 `acl-backup-<时间>-<id>.json`（含修改前的 DACL）与同名 `.restore.ps1`，工具和命令的输出里也会给出可直接执行的恢复命令。恢复脚本把备份里的 DACL 原样写回（同样只写 DACL 段），重复执行是安全的。

## 限制

- 工作区权限部分仅 Windows；其他平台的工具返回 `unsupported`。
- 第一次给大目录追加可继承权限项时，Windows 会把继承传播到整棵子树，可能耗时数十秒（受 `timeoutMs` 约束）。
- 如果原权限项是**继承**来的，修复后该用户在这个目录上会有一条显式完全控制权限项；之后父目录的权限变化不再自动影响这一条。这是为了让 DSH 的沙箱授权有稳定的前置条件。
- 如果 ACL 中存在针对当前用户、覆盖「取得所有权」的 Deny，追加允许项不会生效：脚本会用备份 DACL 撤销修改并报告 `repair-not-effective`。
- 插件运行在 DSH 宿主进程内，不受会话沙箱约束——修改文件权限本身就必须如此；这也意味着安装本插件等于信任它会遵守上面这些边界。
- 提权规则匹配的是**命令字符串**（前缀或正则），不是 argv；`allowShellOperators: false` 只挡住连接符/重定向/子表达式，命令内部的语义（PowerShell 函数、参数内插值）仍可能超出前缀的字面意思——规则要写窄。
- 被放行的那条命令在其**整个执行期间**（含它启动的子进程）拥有完全权限，不是「只放行某个文件操作」。
- 只影响带 `sandbox_permissions` 的调用；普通受限命令的行为不变。
- 提权部分与平台无关；工作区权限部分仅 Windows。

## 信任目录：把「多个公共可写根」做成一等公民

### 机制

DSH 的 Windows 沙箱用「受限令牌 + 能力 SID + 低完整性」判定写入：目标对象必须同时 (1) 在 DACL 里给当前工作区的能力 SID 一条写 ACE，(2) 带 Low 完整性标签。工作区根本身就是这两条的载体，且 ACE 会继承到子目录。

所以「扩大可写范围」不需要改沙箱，只需要把这两条复制到别的目录上：

- 能力 SID 从**当前工作区根读出**，不自行派生（派生方式在 DSH 内部，读出来才不会漂移）；
- 标签同样从工作区根读出（`S:AI(ML;OICI;NW;;;LW)`）。

授权是**按工作区**的：SID 由规范化的工作区路径哈希得到（`dsh-sandbox-windows-acl` 的 `workspaceWriteSid`），跨会话、跨重启稳定；换一个工作区就是另一个 SID，需要再补一条 ACE。会话启动时对配置的每个 root 自动补齐，重复授权幂等。

### 安全代价（这是这个功能的核心取舍）

标签一旦降到 Low，该目录对**任何**低完整性进程可写，不只是 DSH 会话。ACE 又是 `(OI)(CI)` 继承的——授权一个目录等于授权整棵子树。所以：

- 硬禁止：盘根、用户主目录及其祖先、PATH 上的目录、`C:\Windows`、`Program Files`；
- 需显式 `acknowledgeRisk: true`：`%LOCALAPPDATA%`/`%APPDATA%` 根、顶层含可执行文件、包含当前工作区的目录。

### 与 cache 重定向的关系

另一种做法是把缓存重定向进工作区或会话 TEMP（改环境变量），不放宽边界；代价是要按工具维护变量表，且 `$env:TEMP` 每个会话都变、缓存不持久。信任目录走的是另一条：不改命令、缓存留在原地、跨会话复用，代价是边界变宽。两者可以并存，但不建议同时用于同一个目录。

### 界面（client.js）

左侧栏条目注册到 `sidebar.panellist`（`dsh-client-ui-sidebar` 拥有该 slot），但**这个 slot 只取图标**：`PanelIcon({ size, active })` 只渲染该条目的组件，标签来自 `label`。真正的页面注册到 keyed 的根 slot `main`，`key` 必须与 `panellist` 的 `id` 相同——`layout.selectPanel(id)` 会校验 `main` 里存在同 key 的条目，否则抛 `main panel ... is not registered`。点左侧图标即选中该面板，主区域渲染 `main` 中对应条目；页面里的「返回对话」调用 `layout.selectPanel(null)`。

第一版把整块内容直接注册进了 `panellist`，于是它被当成图标渲染、在侧栏里铺成一大块——已按上面的两处注册修正。

面板分两层：**清单**（全局偏好）由面板写入 volatile 配置 `trustRoots`——字段经 `configForms` 实时读写，保存即生效、无需重启，也**不需要会话 id**；**授权**（按工作区）由 Host 在 `tools/pre-execute` 按 TTL 检测清单变化、以及会话创建/启动时对已注册工作区补齐。`.volatile()` 是 schemastery 的方法，字段因此解析成「稳定引用 + `.get()`」，Host 每次读 `.get()` 拿最新值。授权状态是可选的附加信息：只有能拿到会话时才通过 `/trust list --json` 读取，拿不到不影响编辑。风险项不在面板确认（面板没有环境信息），而是在行尾写 `!ack`，Host 在授权时跳过未确认的项。样式参照 VSCode 设置页：等宽路径、行分隔、主按钮、折叠帮助区，颜色走 `currentColor`/`color-mix` 继承宿主主题。

撤销用**对账**而不是列表操作：上一次的清单持久化在 `last-trust-roots.json`，清单变小时对“被移除的路径”遍历已注册工作区逐个撤销该工作区的 SID，并在目录上不再有任何 `S-1-4-*` ACE 时清掉 Low 标签。`verified` 的含义是“本工作区的 SID 已不存在”，不是“目录上没有任何能力 ACE”——多个工作区可以同时信任同一个目录。
