# MCP 服务器面板

左侧栏多一个 **MCP** 入口，点开就是一个 MCP 服务器管理页：列出 DSH 当前的
MCP 服务器，能添加、修改、停用、删除，并用状态点显示连接结果——绿色表示连上
了，红色表示失败并附上简短原因，点一下状态点就会重新检测。

## 界面

- **顶部工具栏**：添加服务器、刷新、依次检测，右侧是汇总（共几个、几个已连接、
  几个失败）。
- **面板管理的服务器**：每个服务器一行，从左到右是状态点、名称、传输类型
  （STDIO / HTTP）、当前状态、启动命令或 URL、状态细节和操作按钮。
  - 「检测」或直接点状态点：向 Host 发起一次一次性探测（连接、列出工具、关闭），
    结果显示在名称右侧，并保留到实时状态下一次变化。
  - 「重启」：重建这个服务器实例，并重置它的重连预算。
  - 「编辑」「停用/启用」「删除」（删除需要再点一次确认）。
- **配置行与插件提供的服务器**：只读区。这里列出 `cordis.patch.yml` 里由其它
  配置层写入的 `@deepseek-ai/dsh-mcp-client` 行（例如 magpie 写的那批
  `magpie-mcp-*`），以及插件在运行时注册的服务器。状态点显示的是它们的加载
  阶段（已加载 / 加载中 / 加载失败 + 诊断），不是连通性。

## 状态点的含义

| 颜色 | 含义 |
| --- | --- |
| 绿 | 已连接；旁边给出当前注册的工具数量。探测通过时也显示绿色。 |
| 琥珀 | 连接中、重连中（带重试次数和上次错误）、等待凭据。 |
| 红 | 失败：`重连次数用尽`、`未启用重连`、`连接未能正常关闭`、`实例加载失败`、`清理失败`，后面跟上一次错误。 |
| 灰 | 已停用、已关闭，或还没检测过。 |

蓝色脉动表示正在探测或正在连接。

## 保存到哪里

面板通过 `settings` Remote 写 profile 的 `cordis.patch.yml` 里 `mcp-manager`
行的 `servers` 字段。每次保存是一次带版本校验的写入，Host 收到后立刻协调：
新增即挂载、改字段即重建该实例、删除即卸载，不需要重启 DSH。

名称同时是工具命名空间，所以不能重名：如果配置文件里已经有一行静态
`dsh-mcp-client` 用着同一个名字，面板里同名的条目会以「名称被占用」失败，
状态点变红并说明原因。

密钥请用凭据模板：在 `env` 或 `headers` 的值里写 `${credential:NAME}`，不要
把明文写进配置。

## 限制

- 静态 `dsh-mcp-client` 行在面板里只读。要把某个行交给面板管理，先在
  `cordis.patch.yml` 里删掉那一行，再用「添加服务器」重建同名条目。
- 探测 STDIO 服务器会真的起一个进程，所以「依次检测」是逐个跑的。
- 没有 OAuth 流程：需要授权的服务器会表现为连接失败。
- 只管理 mcp-manager 这一层；由 agent preset 组合出来的 MCP 实例不会出现在
  这里。
